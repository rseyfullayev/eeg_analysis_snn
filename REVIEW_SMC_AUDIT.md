## 0. Executive summary

1. **A layout bug in `precompute_features.py` silently corrupts every Phase 1B feature file.** The encoder is time-first (`T, B, C, H, W`) everywhere else in the repo, but precompute feeds it `(K_windows, T_frames, C, H, W)` without permuting. The saved per-bag tensor therefore has **exactly 32 rows = frame indices averaged over windows**, not one row per window. **Owner correction (2026-10-19): blast radius on history is nil** — only Phase 1A has actually been run; the 1B experiments that consumed these files were exploratory and produced no retained numbers (Proxy-A 64.10% and the LOTO probes were computed on 1A features via correctly-permuted extraction paths). B1 remains catastrophic for the pipeline-to-be: every future 1B artifact would inherit it. **Fix applied in Stage 0 tranche 1 (§8).** (§3, B1)
2. **`run_phase1b_t0_t5.py` cannot even start**: it imports `get_encoder`, which does not exist (`ImportError` verified), and raw-loads a Hydra config whose `data:`/`model:` sections only exist after composition (verified). Its T5 rank selection also silently drops the subject-probe half of the acceptance criterion from `update.md`. (§3, B2)
3. **The currently-active Phase 1B objective (`SubjectEraserLoss` + GRL/DANN + learned softmax α-head) uses three mechanisms the paper's Failure Catalogue explicitly condemns** (DANN/GRL = known-dead; learned α-head = calibration failure; soft orthogonality instead of the nullspace projection). (§4)
4. The derived objective's core machinery — **Sinkhorn unbalanced OT term, exact E-step α, β-weighted queue readout, readiness gate g and λ_OT, ρ_y fixed point, R_b sufficient-statistic readout, (1−α)-weighted subject scatter U** — has **zero lines of implementation**. What exists (DCL anchor, queue, momentum encoder, LOTO masking) is a correct but partial substrate. (§4 mapping, §5 plan)
5. Redundancy is severe: `train.py` is a 1757-line monolith with an 8-branch dynamic batch unpack, two competing GRL/VIB annealing schedules that overwrite each other in the same batch, ~200 lines of duplicated DCL machinery between `ContrastiveLoss` and `SupMoCoLoss`, three separate feature extractors, two identical `train_backup.py` copies, and config key collisions between composed groups and `_self_` blocks where the "winner" is silent. (§2)
6. **~25 silent-fallback paths** let runs proceed with substitute, guessed, or zeroed state (fabricated zero tensors for unreadable files, `except: balanced_acc = 0`, zero-loss early outs, `strict=False` loads, `loso` unset → training on an empty validation set, Fourier-mixup cache that silently reuses stale statistics, a `--calibrate` mode that computes and prints but never writes). Listed exhaustively in §3.5 because they are the class of defect you have declared unacceptable.
7. **A live Telegram bot token + chat_id is committed in plaintext** (`config/logger/telegram/default.yaml`). **Owner decision (2026-10-16): deferred — remove/rotate when the repo becomes public.** Noted once as a scheduled publication-time task (B20), not an open alarm.

## 3. Bug catalogue

Severity: **S** = corrupts results / blocks runs · **A** = wrong behavior in active paths · **B** = latent/fragile · **C** = hygiene. Verification: [V] = verified by reading code + (where possible) executing; [S] = suspicion, mechanism shown, not reproduced.

### 3.1 Catastrophic

**B1 [V] — Precompute feeds the encoder windows-as-time; every `precomputed_features/bag_*.pt` is scrambled.**
`generate_dataset.py:181-182` saves each window as `(T=32, C=5, H=32, W=32)` (traceable: wavelet returns `(1, 62ch, 5bands, Time)` per `data_process/wavelet.py:99-100`; unfold+permutes → `topo(...)` → `(W_windows, 32, 5, 32, 32)`, saved per-window `video_batch[k]`).
Every other call site permutes to time-first before the encoder (`neurons.py:173` asserts `T, B, C, H, W`; `train.py` ~line 683 `permute(1,0,2,3,4)`; `run_phase1b_t0_t5.py:41`; `_extract_feats` in train.py).
`precompute_features.py:52` does **no permute**: `bag_video = torch.stack(loaded_tensors)` → `(K, 32, 5, 32, 32)` → `encoder(bag_video)` treats **K windows as the time axis** (membrane state accumulates *across windows*; BiTSM shifts *across windows*) and the 32 frames as batch.
`precompute_features.py:54-57`: `features.mean(dim=[0,3,4])` over `(K, 32, 256, 1, 1)` → **(32, 256)** — rows are *frame indices averaged over all windows of the trial*, not windows.
Consequences: (i) every Phase-1B bag has exactly 32 "windows"; (ii) per-window identity — the whole point of MIL/burst detection — is destroyed; (iii) `collate_precomputed` masks (`dataset.py:434-448`) pad/attend rows that are not windows; (iv) reported Phase-1B/DANN/entropy numbers describe frame-averaged trial embeddings, which plausibly explains the ~30% cross-subject floor being *invariant to the 1B machinery*.
Fix: `bag_video.permute(1,0,2,3,4)` before `encoder(...)`, mean over `[0,3,4]`, assert `out.shape[0] == K` and K ∈ [expected window count]; re-run precompute. Add a shape unit test with a synthetic bag.
Caveat: if the deployed `precomputed_features/` dir was generated by an older version of the script, old files may differ — regenerate regardless and diff row counts per bag (should vary per trial, not be constant 32).

*Owner note (2026-10-19): the ea_fda_vib_1b / DANN / entropy numbers discussed in this report were experimental Phase-1B runs whose outputs are discarded, not reported — so no historical metric needs re-measurement for B1; the consequence list above describes the corruption mechanism, which is still pipeline-critical and now fixed + guarded (v2 schema, strict legacy-refusal loader, constant-32 canary, unit tests).*
